# 제3본부 — 주간업무보고 본부 (구축 명세)

## 목표
기존 'SW 미래체험 본부' 및 '정부지원사업 본부'와 별개로 운영하는 제3본부.
3명의 직원이 각자 작성하는 주간 업무를 취합하고 매주 월요일 용역사 교육현황 자료를 반영하여 공통 주간업무보고서 초안을 생성한다.

## 역할·권한
- 관리자(보고서 담당자): 보고 주차 생성, 3명 업무·교육실적 확인, 최종 수정·확정, 문서 출력
- 직원 1/2/3: 자신의 해당 주차 입력·수정·제출; 타 직원의 원본은 기본 수정 불가
- 용역사: 본부 로그인 권한 없음. 교육현황 자료는 관리자가 업로드
- 다른 두 본부: 직원에게 노출/접근 불가 (메뉴 숨김에 그치지 않고 서버 권한 검증 필수)

## 주간 처리 흐름
1. 월요일: 관리자에게 용역사 교육현황 제출 요청/수신
2. 관리자: 교육현황 파일 업로드, 대상 기간·합계·단위 검증
3. 직원 3명: 개인별 '금주 실적 / 차주 계획 / 주요 이슈·협조 요청' 작성 또는 초안 생성 후 검토·제출
4. 시스템: 제출 현황 0/3~3/3과 누락 항목 표시
5. AI: 교육현황과 3명 업무를 취합하여 지정된 기관 보고서 양식으로 중복 정리, 문체·용어 통일
6. 관리자: 근거 자료 비교, 누락·수치 검증, 최종 확정
7. HWPX/DOCX/PDF 중 검증된 출력 형식으로 내보내기

## 보안 요구사항
- 회사 메일 원본 자동 수집 금지(별도 승인 전).
- 교육현황은 개인정보 최소화 후 업로드. 이름·연락처 등 개인정보 탐지되면 기본 차단·검토.
- 공유는 '제3본부 화면만'이 아니라 서버 API 및 DB에서 본부별 역할 제한.
- GitHub Pages/정적 사이트의 URL 비공개, 메뉴 숨김만으로는 접근통제가 되지 않음.
- 직원 입력 자료·교육현황·인증 토큰을 공개 GitHub 저장소나 브라우저 localStorage에 보관하지 않음.
- 원본·생성본·승인본 변경 이력 및 수정자/시각을 기록.

## 구현 순서
1. 제3본부 독립 UI/권한 체계
2. 직원 3명용 개인 입력 및 제출 현황
3. 용역사 교육현황 업로드·검증
4. 취합 초안 및 관리자 최종 승인
5. 기존 월요일 실행과 연계, 문서 파일 출력
6. 3계정 권한 테스트 및 개인정보/수치 검증 테스트

## 미확정 사항
- 실제 직원 계정·인증 방식
- 현재 사용하는 주간업무보고서 HWP/HWPX 서식
- 용역사 교육현황 실제 파일 형식 및 표 항목
- 승인된 DB/백엔드 배포 환경
이 네 항목이 정해지기 전에는 실제 직원 공동편집 및 안전한 공유를 활성화하지 않는다.
